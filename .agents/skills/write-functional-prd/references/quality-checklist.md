# PRD 交付检查

## 内容完整性

- 背景能够说明现状、问题和建设目标。
- 角色职责、功能权限和数据范围不存在缺口。
- 本期范围与不在本期范围明确。
- 核心流程包含必要的失败、中断和恢复处理。
- 关键操作说明了前置条件、系统处理和结果。
- 外部依赖说明了数据关系和本期关系。

## 一致性

- 功能清单中的本期功能均有对应的详细需求。
- 页面操作符合角色权限和数据范围。
- 按钮或操作条件与状态、校验规则一致。
- 同一术语、状态和业务对象全篇名称一致。
- 同一规则只完整出现一次。
- 待确认问题不与正文中的确定结论冲突。

## 精简度

- 不包含字体、颜色、尺寸、间距、坐标等视觉规格。
- 不复述原型已经清楚表达的布局和通用交互。
- 不包含页面美观、体验提升等空泛描述。
- 不包含代码结构、数据库表和具体技术方案。
- 不存在空章节、空表格、重复段落和无意义附录。
- 每段内容都会影响功能、数据、状态、权限、异常、依赖或范围。

## 可实现性

- 研发能够判断谁在什么条件下执行操作。
- 研发能够判断操作成功后哪些数据或状态发生变化。
- 研发能够判断校验失败或依赖异常时如何处理。
- 表单字段的必填、默认值、数据来源和校验口径足够明确。
- 列表的查询范围、筛选、排序和分组规则足够明确。
- 未确定且影响实现的问题已集中列出，没有被擅自补全。

发现任一问题时，先修改 PRD，再进行交付。
