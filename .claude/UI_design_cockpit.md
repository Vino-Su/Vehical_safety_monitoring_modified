# 可视化驾驶舱 UI 设计规范

> 适用范围：智能网联汽车安全监测平台的可视化驾驶舱、高保真大屏原型及其公共组件。
>
> 当前阶段仅约束视觉系统、布局方式、适配策略和通用交互，不规定任何具体页面的业务指标、图表数量或模块内容。

## 1. 规范定位

### 1.1 与 WEB 管理端的关系

驾驶舱与 WEB 管理端属于同一产品体系，但服务于不同使用场景：

- WEB 管理端面向录入、查询、审批、处置等高频操作，继续遵循 `UI_design.md` 的浅色 Ant Design 规范。
- 驾驶舱面向全局态势感知、集中值守和汇报展示，采用深色、单屏、远距离可读的可视化语言。
- 两端必须共享产品名称、业务术语、数据口径、权限口径和状态颜色语义，不得为追求视觉效果改变业务含义。
- 驾驶舱不复刻 WEB 页面的侧边栏、面包屑、分页表格和表单布局，也不得简单地将 WEB 页面切换为深色主题。

### 1.2 规则优先级

1. 驾驶舱页面优先遵循本文件。
2. 本文件未规定的字体、技术栈和业务状态语义，继承 `UI_design.md`。
3. 具体页面内容以 `01-需求文档` 和 `02-产品文档` 为准。
4. 业务需求与视觉规范冲突时，先保证信息完整、准确、可辨识，再调整表现形式。

### 1.3 设计目标

- **一屏总览：** 核心态势在一个视口内完整呈现，默认状态不产生页面级滚动。
- **远距可读：** 重要信息在会议室、指挥中心等观看距离下仍可快速识别。
- **层级明确：** 一个画面只设置一个第一视觉中心，避免所有模块等权竞争。
- **克制可信：** 体现监管平台的专业性，避免夸张霓虹、廉价科幻和纯装饰动画。
- **实时可感：** 对更新时间、连接状态和异常变化提供明确反馈，但不持续干扰观看。
- **双比例原生适配：** 16:9 与 32:9 使用同一设计系统、不同布局模式，不做机械拉伸。

## 2. 目标画布与显示模式

### 2.1 基准画布

| 模式 | 基准分辨率 | 常见兼容分辨率 | 主要场景 |
| --- | ---: | ---: | --- |
| 标准宽屏 `standard` | 1920 × 1080（16:9） | 1366 × 768、2560 × 1440、3840 × 2160 | 普通大屏、会议室屏幕、桌面全屏预览 |
| 超宽屏 `ultrawide` | 3840 × 1080（32:9） | 5120 × 1440 | 超宽显示器、双块 16:9 拼接屏、指挥中心横向大屏 |

设计稿和高保真页面必须至少覆盖 `1920×1080` 与 `3840×1080`。其他分辨率依据对应模式等比扩展并重新分配剩余空间。

### 2.2 模式判定

- 视口宽高比小于 `2.4` 时使用 `standard` 模式。
- 视口宽高比大于或等于 `2.4` 时使用 `ultrawide` 模式。
- 21:9 等中间比例默认沿用 `standard` 模式，通过扩展中心区域或两侧留白吸收额外宽度，不提前切换为 32:9 架构。
- 页面根节点应支持 `data-layout="standard|ultrawide"` 人工覆盖，便于演示、截图和特殊拼接屏部署。

推荐使用纵横比媒体查询，不以设备名称或单一宽度判断：

```css
.cockpit-root {
  width: 100vw;
  height: 100vh;
  height: 100dvh;
  overflow: hidden;
}

@media (min-aspect-ratio: 12 / 5) {
  .cockpit-root {
    --layout-mode: ultrawide;
  }
}
```

### 2.3 缩放原则

- 页面使用 CSS Grid/Flex 和稳定的宽高约束进行重排，不得通过横向压缩或拉伸整张画布适配屏幕。
- 组件尺寸以 `1080px` 高基准制定；更高分辨率可采用离散尺寸档位或基于视口高度的统一比例，不按视口宽度放大字号。
- 文字不得使用纯 `vw` 字号，避免 32:9 下文字异常放大。
- 地图、图表和列表应使用可用空间重绘，不得使用位图整体放大。
- 全屏模式固定 `overflow: hidden`；内容不足时增加呼吸空间，内容过多时减少非核心信息，不使用页面滚动补救。
- 浏览器缩放以 `100%` 为验收基准；实际部署前需结合屏幕物理尺寸和观看距离进行一次现场字号校准。

## 3. 双比例布局系统

### 3.1 通用结构

驾驶舱由以下空间层级组成，具体页面可按需求选用，但不得预设具体业务内容：

1. **全局层：** 页面标题、品牌、当前时间、数据更新时间、连接状态及全局操作。
2. **主舞台层：** 当前页面唯一的第一视觉中心，可承载地图、核心图形或主态势视图。
3. **辅助分析层：** 围绕主舞台组织的指标、趋势、排行、事件或说明信息。
4. **浮层：** 图例、提示、筛选、详情或异常提示，不永久遮挡主舞台关键区域。

### 3.2 16:9 标准宽屏

- 使用 `24` 列栅格，外边距 `24px`，列间距 `12px`，纵向模块间距 `12px`。
- 顶部全局栏建议高度 `72-80px`，主体占据剩余高度。
- 默认采用“左辅助区 + 中央主舞台 + 右辅助区”三段式构图。
- 左右辅助区各占 `5-6` 列，中央主舞台占 `12-14` 列；可依据主视觉类型微调，但主舞台不得小于主体宽度的 `48%`。
- 底部若设置横向分析带，其高度原则上不超过主体可用高度的 `24%`，不得压缩主舞台至不可读。
- 第一视觉中心应接近画面几何中心，重要弹层应避开顶部标题区和左右高密度信息区。

### 3.3 32:9 超宽屏

- 使用 `48` 列栅格，外边距 `32px`，列间距 `16px`，纵向模块间距 `12-16px`。
- 顶部全局栏建议高度 `72-80px`，不得随宽度成比例增高。
- 采用“左侧分析域 + 中央主舞台域 + 右侧分析域”的独立超宽构图，严禁把 16:9 画布直接拉伸至全宽。
- 中央主舞台建议占 `18-22` 列，两侧分析域合计占 `26-30` 列；两侧可以拆分为多列，但视觉权重必须低于中央主舞台。
- 两侧新增空间优先用于并列展示互补信息、扩展时间跨度或增加空间上下文，不得单纯放大卡片、数字和留白。
- 模块的垂直层级应左右呼应，避免一侧堆满、一侧空置导致重心偏移。
- 超宽模式下模块最大文本行宽建议不超过 `36` 个汉字；过宽区域应拆列，不形成横跨半屏的长段文字。

### 3.4 双屏拼接缝安全区

32:9 可能由两块 16:9 屏幕拼接，必须支持中心拼接缝场景：

- 在水平中心线两侧各预留至少 `48px` 的关键内容安全距离，形成总宽至少 `96px` 的拼接缝安全区。
- 页面标题、关键数字、图例、按钮、弹窗、图表坐标轴标签和主要定位点不得压在拼接缝上。
- 主舞台可跨越拼接缝，但关键标注、交互控件和默认聚焦点必须可偏移至安全区外。
- 装饰线和背景可以跨缝，具有业务含义的线条、路径和文字必须在拼接屏场景下可识别。
- 根节点应提供 `data-seam="on|off"` 配置；单块超宽屏关闭拼接缝补偿后，仍保持整体构图平衡。

### 3.5 安全边距

- 16:9 外围安全边距不得小于 `24px`；32:9 不得小于 `32px`。
- 顶部标题与屏幕边缘的安全距离不得小于 `24px`。
- 底部信息不得贴近系统任务栏或大屏物理包边，底部安全距离不得小于 `20px`。
- 投屏、视频墙存在裁切风险时，启用 `overscan-safe` 模式，将四周安全边距提升至画面宽高的 `2%`。

## 4. 视觉语言

### 4.1 风格定位

整体采用“城市运行指挥中枢”风格：以深海军蓝为环境底色，以青色表达实时信号，以高明度蓝色表达品牌、选中和空间边界。界面应深色、克制、清晰，具有实时数据氛围；视觉记忆点来自中央地图或核心图形、稳定的左右分析秩序以及精确的数据变化，而不是装饰性发光边框。

视觉方向必须满足以下要求：

- 空间态势类页面优先采用“中央主舞台 + 两侧分析域”，中央地图或城市模型约占主体宽度的 `50%-65%`。
- 深海军蓝只承担环境和层级，青色只承担实时、活跃和数据轨迹，高明度蓝色承担主操作、选中和边界；不得用多个近似蓝色表达不同业务状态。
- 模块标题采用“短青色竖线或短下划线 + 标题文字”的轻量锚点，同一页面只能选择一种形式。
- 允许对关键地图边界、实时点位和选中态使用局部微光，但常规模块、正文和静态图表不得普遍发光。
- 信息密度应服务于快速扫读；同一视区优先展示结论、变化和异常，禁止为了还原传统大屏观感而堆满图表。

禁止以下常见做法：

- 全屏蓝色渐变、紫蓝渐变或单一蓝色系堆叠。
- 大面积霓虹外发光、扫描线、粒子、网格地球等与业务无关的装饰。
- 所有模块都使用完整描边卡片，或出现卡片嵌套卡片。
- 3D 饼图、3D 柱图、透视变形图表和无意义仪表盘。
- 为填满画面而重复指标、放大数字或添加虚假实时数据。

### 4.2 基础色板

所有颜色必须通过 CSS 变量统一维护，不得在组件中随意新增近似色。

| Token | 色值 | 用途 |
| --- | --- | --- |
| `--cockpit-bg` | `#071522` | 页面主背景，深海军蓝 |
| `--cockpit-bg-raised` | `#0B1C2A` | 抬升区域、浮层背景 |
| `--cockpit-surface` | `#10263A` | 模块内容底色 |
| `--cockpit-surface-soft` | `#163247` | hover、选中和次级区域 |
| `--cockpit-border` | `#24465A` | 分隔线、弱边框 |
| `--cockpit-border-strong` | `#3D7088` | 聚焦边框、关键分隔 |
| `--cockpit-text` | `#F2F6F9` | 主要文字 |
| `--cockpit-text-secondary` | `#A7BAC8` | 次要文字 |
| `--cockpit-text-muted` | `#688395` | 辅助文字、坐标轴 |
| `--cockpit-primary` | `#1677FF` | 品牌主色、主操作、预警语义 |
| `--cockpit-cyan` | `#00CFE8` | 实时数据、轨迹、活跃点位 |
| `--cockpit-cyan-soft` | `#BDEFFF` | 关键数据高亮、选中标注，不作大面积背景 |
| `--cockpit-map-land` | `#123A43` | 深色矢量地图陆地区域 |
| `--cockpit-map-road` | `#38627A` | 次要道路与地理线 |
| `--cockpit-map-boundary` | `#13C8F5` | 行政边界、重点区域轮廓 |
| `--cockpit-green` | `#52C41A` | 正常、在线、已完成 |
| `--cockpit-yellow` | `#FADB14` | 注意、事故点位或待关注状态 |
| `--cockpit-orange` | `#FA8C16` | 告警、处理中 |
| `--cockpit-red` | `#FF4D4F` | 高风险、错误、紧急状态 |
| `--cockpit-purple` | `#9254DE` | 独立分类辅助色，不承担风险等级 |

背景应以深海军蓝、冷灰和低饱和青色形成层次，不能用不同明度的蓝色填满所有区域。建议首屏可见面积中背景与地图底色约占 `70%-80%`，文字和中性色约占 `15%-20%`，高饱和青蓝及状态色合计不超过 `10%`。紫色只允许作为独立分类辅助色，不使用紫色顶栏或紫蓝渐变作为默认主题。

### 4.3 状态颜色继承

- 预警：`#1677FF`，必须配合“预警”文字或图形标识。
- 告警：`#FA8C16`；高优先级或紧急告警可升级为 `#FF4D4F`。
- 正常/在线：`#52C41A`。
- 事故或需关注点位：`#FADB14`。
- 离线/未知：`#748390`。
- 同一颜色在同一页面不得同时表达两个相互冲突的业务状态。
- 任何状态不得仅依赖颜色表达，必须同时提供文字、图标、线型或形状中的至少一种辅助编码。

### 4.4 背景和质感

- 主背景以纯色或低对比度分层为主，可使用从 `#071522` 到 `#0B1C2A` 的轻微纵向明度过渡，但不得形成可感知的装饰性渐变带。
- 可叠加非常轻微的噪点、道路纹理或地理网格，透明度建议 `2%-6%`；纹理必须服务于空间语境，不得影响图表和文字读取。
- 模块使用半透明背景时必须保证文字对比度；地图上方的浮层应增加实色遮罩，避免底图干扰阅读。
- 阴影用于区分浮层与底层，不用于装饰。推荐 `0 8px 24px rgba(0,0,0,.28)`，常规模块不使用重阴影。
- 常规模块圆角 `4px`，弹层最大 `6px`；不得使用胶囊形容器包裹普通文字。
- 允许以短线、局部强调边和小面积色块建立节奏，不使用四角装饰框和复杂机械边框。
- 局部微光仅用于地图边界、点位、轨迹和当前选中项，推荐 `0 0 8px rgba(0,207,232,.35)`；模糊半径不得超过 `12px`，且不得叠加在正文上。

## 5. 字体与数字

### 5.1 字体族

- 中文：`"HarmonyOS Sans SC", "Source Han Sans SC", "PingFang SC", "Microsoft YaHei", sans-serif`。
- 英文：`"SF UI Text", "Segoe UI", Arial, sans-serif`。
- 数字：优先 `DIN` 或 `Bahnschrift`；未安装时使用 `"Segoe UI", Arial, sans-serif`。
- 不为驾驶舱额外加载影响首屏性能的在线字体。
- 指标数字使用 `font-variant-numeric: tabular-nums lining-nums`，确保实时刷新和列表纵向对比时数字不跳动。
- 同一组件内的中文、英文和数字必须保持统一基线；不得为了营造科技感使用斜体、描边字、空心字或过宽字距。

### 5.2 1080 高度基准字号

| 层级 | 字号 / 行高 | 字重 | 用途 |
| --- | --- | --- | --- |
| 全局标题 | `28px / 40px` | 600 | 页面名称，仅一处 |
| 核心数字 XL | `48px / 56px` | 600 | 极少数第一层级核心值 |
| 核心数字 L | `36px / 44px` | 600 | 主要指标值 |
| 核心数字 M | `28px / 36px` | 600 | 次级指标值 |
| 模块标题 | `18px / 26px` | 600 | 模块分区标题 |
| 重点正文 | `16px / 24px` | 500 | 重点标签、列表主信息 |
| 标准正文 | `14px / 22px` | 400 | 常规正文、图例、表格 |
| 辅助文字 | `12px / 18px` | 400 | 坐标轴、单位、更新时间 |

- `12px` 是 1080 高度画布的绝对最小字号，仅用于非关键辅助信息。
- 核心数字不得全部使用 XL；同一屏幕最多设置一组 XL 层级。
- 数字与单位分级显示，单位通常比数值小 `12-20px`，基线对齐。
- 标题和数字字距为 `0`，不得使用负字距；英文大写缩写可使用不超过 `0.04em` 的正字距。
- 文本容器必须设置稳定宽度或最大宽度，长文本优先换行，其次省略并提供完整信息查看方式。

## 6. 间距、线条与图标

### 6.1 间距体系

- 基础间距单位为 `4px`。
- 常用间距：`4 / 8 / 12 / 16 / 24 / 32 / 40px`。
- 模块内边距：常规 `16px`，高密度区域 `12px`，核心模块可用 `20-24px`。
- 模块之间：常规 `12px`，一级区域之间 `16-24px`。
- 不得通过无规则负 margin 强行对齐，也不得依靠绝对定位堆叠主要布局。

### 6.2 线条

- 常规分隔线 `1px`，颜色使用 `--cockpit-border`。
- 选中或聚焦边 `2px`，颜色使用对应状态色或主色。
- 图表网格线透明度建议 `8%-16%`；主次网格必须可区分。
- 轨迹、趋势等具有方向的信息应同时使用颜色、线型或节点形状表达，不仅靠线宽区分。

### 6.3 图标

- 优先使用项目已启用的 Lucide 图标，不手绘相同语义的 SVG。
- 常规图标尺寸 `16/20/24px`，全局操作最大 `28px`。
- 线性图标描边建议 `1.75px`，同一区域保持一致。
- 图标按钮使用正方形稳定尺寸，常规 `36-40px`；仅图标操作必须提供 tooltip 和可访问名称。
- 不使用表情符号充当业务图标，不混用线性和填充风格图标。

## 7. 通用组件规范

### 7.1 顶部全局栏

- 高度稳定，不随内容或画面宽度变化。
- 全局标题在视觉上唯一，不与模块标题争夺层级。
- 时间、数据更新时间和连接状态属于辅助层级，不使用与标题同等字号。
- 32:9 拼接屏开启缝隙补偿时，标题可偏离几何中心，确保完整可读。
- 存在多驾驶舱切换时，导航采用紧凑文本标签；默认态使用次级文字色，选中态使用 `--cockpit-cyan` 的底边、描边或小面积背景三者之一，不同时叠加。
- 顶栏底色使用 `--cockpit-bg-raised` 或与主背景连续的深色遮罩，不使用默认紫色顶栏、高饱和渐变和整条发光描边。

### 7.2 模块容器

- 模块应表现为连续界面中的信息区，不做悬浮卡片墙。
- 优先使用背景层级、局部分隔线和标题锚点划分区域。
- 同一模块仅允许一层容器，不在有边框的模块内再次堆叠完整卡片。
- 模块标题区高度和操作区位置应统一，动态内容不得改变模块外框尺寸。
- 模块标题建议由 `2px × 14-18px` 青色短竖线和标题组成，标题与锚点间距 `8px`；若页面选用短下划线方案，则同屏不得再混用竖线方案。
- 面板底色与页面底色的明度差应控制在可感知但不突兀的范围，禁止依赖完整高亮边框区分每一个模块。

### 7.3 指标单元

- 由名称、数值、单位和可选变化信息组成，阅读顺序固定。
- 数值区域预留最大位数宽度，刷新时不得导致相邻内容跳动。
- 千分位、小数位和单位必须按业务口径统一；无数据使用 `--`，不得显示虚假 `0`。
- 同一区域指标不超过两个数字层级，避免数字墙失去主次。
- 多个总量指标并排时可使用紧凑指标带，单项由图标、名称和数值组成；图标背景只允许小面积使用主色或青色，指标带不得制作成连续高亮蓝色卡片墙。

### 7.4 图表容器

- 标题、单位、图例和绘图区边界必须明确，图例不得遮挡数据。
- 图表在 16:9 与 32:9 下重算坐标和数据密度，不按比例拉伸图形。
- 坐标轴标签不能重叠；空间不足时降低刻度密度、缩写时间或切换布局，不缩小到最小字号以下。
- tooltip 使用 `--cockpit-bg-raised` 实色背景，关键值右对齐，单位完整。
- 无数据、加载中和错误状态必须占据与正常图表相同的稳定区域。

### 7.5 列表与轻量表格

- 驾驶舱只展示适合快速扫读的少量关键列，不直接复用 WEB 端完整业务表格。
- 行高建议 `36-44px`；固定时间、编号居中，文本左对齐，数字右对齐。
- 实时列表采用固定容器高度，可定时轮换或局部滚动，但不得引起模块高度变化。
- 轮换必须提供暂停能力；用户正在 hover、聚焦或查看详情时暂停自动轮换。
- 超出展示数量时使用“更多”或下钻，不在驾驶舱主画面放置传统分页器。

### 7.6 图例与标签

- 图例靠近对应图形放置，顺序与视觉编码一致。
- 状态标签采用图标/色点 + 文字，不使用大面积高饱和背景。
- 标签高度建议 `24-28px`，圆角不超过 `4px`。
- 同一画面图例的颜色、线型和命名必须全局一致。

### 7.7 浮层与弹窗

- 地图提示、图表 tooltip 属于轻浮层；详情、筛选和异常说明使用抽屉或模态层。
- 弹窗不超过视口宽度的 `60%`、高度的 `80%`；32:9 下仍按可读内容宽度控制，不随屏幕无限变宽。
- 弹层出现后保持背景上下文可辨识，遮罩建议 `rgba(0,0,0,.56)`。
- 关闭入口始终可见，支持 `Esc` 关闭；高风险确认不得因自动刷新而消失。

### 7.8 控件

- 驾驶舱默认是低频操作界面，筛选和设置应收纳在浮层或工具栏，不长期侵占主视觉空间。
- 按钮高度建议 `36-40px`；主要操作、次要操作和危险操作必须明确区分。
- 模式切换使用分段控件，布尔设置使用开关或复选框，图层显隐使用复选框，数值范围使用输入框或滑块。
- 所有可点击元素必须有 hover、active、focus 和 disabled 状态。

## 8. 数据可视化规范

### 8.1 图表选型原则

- 比较数量：柱状图、条形图。
- 观察时间变化：折线图、面积图；面积填充透明度不得遮挡多序列比较。
- 表达构成：优先条形图；类别不超过 `5` 个且需要强调占比时可使用环形图。
- 表达排名：水平条形图，默认按值排序。
- 表达空间关系：地图、热力格网或区域着色，必须配套图例和时间口径。
- 表达单一进度：进度条或简洁环形进度，不使用拟物仪表盘。

### 8.2 色彩使用

- 单序列优先使用主色或青色；折线下方可使用同色透明度从 `20%` 到 `0%` 的面积衰减，但不得跨色相渐变。
- 多序列使用离散色板并保持跨图表一致；相邻系列须有足够明度或色相差异。
- 风险状态图表严格使用状态色，不用装饰色替换业务语义。
- 同屏高饱和颜色同时出现不超过 `4` 种，其余系列使用降低饱和度的辅助色。
- 红色和橙色只用于需要关注的状态，不作为普通分类的默认首选色。
- 环形图默认使用细环、中心结论和外置图例，环宽约占半径的 `18%-24%`；分类超过 `5` 个时改用条形图。
- 柱状图优先使用实色或同色明度变化，柱宽保持稳定，不使用高光材质、立体透视和跨色相渐变柱。

### 8.3 标注与口径

- 图表必须显示必要的标题、单位、时间范围和数据更新时间。
- 百分比应说明分母口径；同比、环比必须明确比较周期。
- 截断坐标轴时必须明显标注，不制造夸大的趋势差异。
- 排名、占比和趋势不得使用动画改变数据顺序后仍保留旧标签位置。
- 空值、零值、未上报和计算失败必须使用不同状态表达。

### 8.4 地图和空间视图

- 底图应降饱和、降对比。卫星影像模式增加 `35%-55%` 的深蓝黑遮罩；矢量模式优先使用 `--cockpit-map-land`，行政区边界、道路和业务点位建立清晰层级。
- 建议层级为：地形与水系最低，次要道路和行政标注其次，重点区域边界、业务轨迹和实时点位最高；地图文字不得比业务标注更醒目。
- 地图上的状态色与全局状态色一致，聚合点需同时显示数量与状态提示。
- 点位密集时使用聚合、抽稀或分级显示，不通过无限缩小图标解决遮挡。
- 地图控件固定尺寸和位置，不因点位、标签或图例变化发生位移。
- 重要标注不得同时被侧栏、浮层和拼接缝遮挡。
- 普通实时点位使用 `6-10px` 青色实心圆点，可带一层透明外圈；聚合点和告警点必须通过大小、形状或图标进一步区分，不只更换颜色。
- 行政区或重点道路边界可使用 `1-2px` 青蓝描边和轻微微光；非选中区域降低至 `30%-55%` 不透明度，避免整张地图同时高亮。
- 轨迹线宽建议 `2-3px`，方向使用箭头、渐隐尾迹或节点序列中的一种表达；静态历史轨迹不得持续脉冲。

## 9. 动效与实时反馈

### 9.1 动效原则

- 动效用于解释状态变化、空间定位和层级切换，不用于持续装饰。
- 常规过渡 `160-240ms`，面板展开 `240-360ms`，地图定位依据距离控制在 `300-800ms`。
- 首屏可使用一次轻量分段进入动画，总时长不超过 `800ms`，完成后保持稳定。
- 支持 `prefers-reduced-motion`，关闭位移、脉冲和数字滚动，仅保留必要淡入淡出。

### 9.2 实时数据

- 数据刷新不得让整个模块闪烁或重新进入动画。
- 数值变化可使用 `300-500ms` 的颜色或背景弱提示，随后恢复常态。
- 新增异常可脉冲提示最多 `3` 次，之后保持稳定状态标识。
- 列表更新优先局部插入和位置过渡，避免整表跳动。
- 页面必须展示最近更新时间；超过业务规定时限未更新时，明确进入“数据延迟”状态。

### 9.3 自动轮播

- 仅在信息无法在一屏合理展示且确有轮换价值时使用。
- 单屏停留时间不得少于 `8s`，切换动画不超过 `400ms`。
- hover、键盘聚焦、打开浮层或用户主动操作时暂停轮播。
- 不允许多个区域以不同节奏同时轮播。

## 10. 页面状态与异常处理

每个数据模块至少具备以下状态：

- **加载中：** 使用与最终布局一致的骨架或局部加载提示，不改变容器尺寸。
- **无数据：** 显示“暂无数据”及必要的筛选/时间范围提示，不显示全零假图表。
- **请求失败：** 显示失败原因摘要和重试入口，不用空白区域代替。
- **数据延迟：** 保留最后一次有效数据，明确标记数据时间和延迟状态。
- **连接中断：** 在全局层提示连接状态，各模块保持最后有效画面并停止实时动画。
- **权限受限：** 说明无权限或数据范围受限，不暴露被限制信息的数量或轮廓。
- **全屏受限：** 浏览器阻止全屏时提供可理解的提示，页面仍可正常使用。

错误提示必须说明影响范围。单个模块失败不得使用全屏错误遮挡其他仍可用模块。

## 11. 可访问性与可读性

- 正文文字与背景对比度不低于 `4.5:1`，大号文字不低于 `3:1`。
- 状态不得只靠红绿区分；同时使用文字、图标、形状或线型。
- 所有操作可通过键盘聚焦，焦点样式清晰且不被裁切。
- 不使用每秒超过 `3` 次的闪烁，不持续使用高亮脉冲。
- tooltip、弹窗和抽屉具有明确的焦点进入与返回逻辑。
- 图表应提供可访问名称或数据摘要；核心结论不能只存在于 Canvas 像素中。
- 远距离观看场景下，正文、图例和坐标轴不得低于规定最小字号。

## 12. 技术实现约束

### 12.1 技术栈

- 沿用项目技术栈：`HTML5 + Tailwind CSS v3 + 原生 JavaScript`。
- 不引入新的前端框架，不依赖外部 CDN；公共样式和脚本必须存放于项目内。
- 图表、地图等已有能力优先复用项目现有实现；新增依赖前需确认离线部署和许可证条件。

### 12.2 样式隔离

- 驾驶舱根节点统一使用 `.cockpit-root`，组件样式限定在该作用域内，避免污染 WEB 页面。
- 建立驾驶舱独立 Token，不直接覆盖 WEB 端 Ant Design 变量。
- 所有颜色、间距、字号、层级和动效时长使用 CSS 变量管理。
- 组件中禁止散落无法追踪的硬编码颜色和 `z-index`。

### 12.3 双模式实现

- `standard` 与 `ultrawide` 共享语义化 DOM 和数据逻辑，通过 Grid Areas、列数和模块布局重排。
- 不为 32:9 复制一套独立页面或重复请求相同数据。
- 超宽模式允许同一模块切换内部布局，例如纵向列表改为双列列表，但不可改变数据口径。
- 所有固定格式区域必须定义 `min-width`、`min-height`、`aspect-ratio` 或明确 Grid 轨道，防止动态内容造成布局位移。
- 地图和 Canvas 图表监听容器尺寸变化并重新渲染；不得只修改 CSS 宽高导致画面模糊。

### 12.4 性能

- 首屏优先渲染框架、全局状态和主舞台，再加载次级图表。
- 高频数据更新与图表动画解耦，避免每次推送重建全部 DOM 或图表实例。
- 非可见浮层和非活动视图暂停动画、视频和高频定时器。
- 长列表使用固定条数轮换或虚拟化，不一次渲染大量节点。
- 避免大面积 CSS blur、持续 box-shadow 动画和全屏滤镜。

## 13. 设计与开发验收

### 13.1 必测分辨率

| 分辨率 | 模式 | 验收重点 |
| ---: | --- | --- |
| 1366 × 768 | standard 预览 | 无遮挡、文字不溢出、主要信息可用 |
| 1920 × 1080 | standard 基准 | 完整视觉和交互验收 |
| 2560 × 1440 | standard 扩展 | 空间合理扩展，图表无模糊 |
| 3840 × 1080 | ultrawide 基准 | 独立超宽布局、无横向拉伸 |
| 5120 × 1440 | ultrawide 扩展 | 字号层级稳定、两侧空间有效利用 |
| 3840 × 2160 | standard 4K | 高分辨率资源清晰、布局比例稳定 |

### 13.2 布局验收

- 默认状态无页面级横向或纵向滚动条。
- 所有文字完整、合理换行或省略，无按钮、数字、图例相互遮挡。
- 动态数字按最大位数测试后不引发模块宽高变化。
- 图表坐标轴、图例、tooltip 和地图控件不越界。
- 16:9 与 32:9 均存在明确第一视觉中心，32:9 不是 16:9 的拉伸版。
- 32:9 拼接缝开启时，关键文字和操作不跨越中心安全区。
- 最长中文名称、最大数值、空数据、加载失败和数据延迟状态均完成验证。

### 13.3 视觉验收

- 页面不是单一深蓝配色，状态色使用准确且不过量。
- 首屏形成深海军蓝环境、冷灰信息层和青蓝实时信号的明确分工，高饱和强调面积不超过约 `10%`。
- 不出现卡片套卡片、过度发光、装饰性粒子或无业务含义动效。
- 字号、间距、圆角、描边和图标风格统一。
- 图表选型与数据关系匹配，无 3D 图表和误导性坐标。
- 文本与背景对比度满足本规范要求。
- 空间态势页面的地图或核心图形是唯一第一视觉中心，两侧图表不以更高亮度、面积或动效争夺注意力。
- 地图的底图、道路、区域边界、业务点位和告警点具有可辨识的五级视觉层次，密集点位无大面积粘连。
- 模块标题锚点、顶部导航选中态和局部微光形式全屏一致，不混用多套装饰语言。

### 13.4 功能与截图验收

- 新建重大版本或修复问题后，使用浏览器分别验证 `1920×1080` 和 `3840×1080`。
- 检查模式切换、全屏、浮层、图表 tooltip、地图缩放、异常状态和数据刷新表现。
- 检查浏览器控制台无 JavaScript 错误、资源加载失败和重复请求。
- 验收截图统一保存到 `07-bugs`，文件名包含页面名称、比例与测试时间。

## 14. 页面设计前置检查清单

开始任何具体驾驶舱页面设计前，必须先确认：

- [ ] 使用对象、观看距离和主要使用环境。
- [ ] 部署屏幕是单块超宽屏还是双屏/多屏拼接。
- [ ] 主验收比例是 16:9、32:9，还是两者同等优先。
- [ ] 当前页面唯一的第一视觉中心。
- [ ] 指标定义、时间口径、刷新频率和异常阈值。
- [ ] 哪些信息必须常驻，哪些可通过浮层或下钻查看。
- [ ] 最大文本长度、最大数值位数、空数据和异常数据状态。
- [ ] 32:9 下新增空间承载的互补信息，不以放大和复制填充。
- [ ] 颜色语义与现有 WEB 端、PRD 和其他驾驶舱页面一致。
- [ ] 已制定 1920×1080 与 3840×1080 的浏览器自测方案。
