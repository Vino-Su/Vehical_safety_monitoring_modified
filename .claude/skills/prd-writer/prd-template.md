# PRD撰写结构模板

> 本模板基于车辆管理系统5份实际PRD文档提炼总结，并经4轮优化调整形成。适用于B端企业管理系统的产品需求文档撰写。

---

## 核心原则

1. **业务语义优先**：围绕功能目标、用户操作、数据、权限、规则、状态和异常结果编写
2. **PRD不代替UI Design**：不写颜色、字号、宽高、间距、圆角、阴影、像素位置和技术实现
3. **以业务能力划分功能点**：按独立用户目标和业务结果拆分3.x章节，不按页面、Tab、按钮或弹窗数量机械拆分
4. **表格驱动**：字段、权限、状态、校验和依赖等结构化信息使用表格，表格不包含UI属性
5. **权限融入操作**：对每项操作说明可执行角色、数据范围和前置条件
6. **枚举值就地定义**：枚举值直接写入对应字段的业务说明，不设独立章节
7. **固定章节语义**：各子章节编号与含义固定，无内容时可省略但不改号，保持跨PRD一致
8. **规则单一来源**：局部规则写在对应功能章节，跨功能规则写在第4章，避免重复
9. **名词先解释再使用**：关键术语在名词解释章节统一说明，确保全文理解一致
10. **文档格式极致紧凑**：仅允许单个表格后空一行以提升可读性，其他位置禁止插入空行，大章节间仅使用`---`分隔线

## 🔑 功能详细设计编排规则

**功能点划分原则：**
- **独立业务目标**：能明确表述用户目标、触发条件和成功结果的能力，作为一个3.x章节
- **同一目标合并**：同一目标下的查询、新建、编辑、删除、导出等操作在同一功能章节中说明
- **视图不决定功能拆分**：页面、Tab、弹窗和按钮仅是功能承载方式，不作为独立拆分依据

**子章节取舍规则（无内容可省略，但编号与含义固定）：**

| 子章节 | 是否必需 | 包含条件 |
| ------ | -------- | -------- |
| 3.x.1 功能目标与范围 | 必需 | 每个功能点必须有 |
| 3.x.2 使用条件与权限 | 可省略 | 存在角色、数据范围或前置条件差异时包含 |
| 3.x.3 数据与字段规则 | 可省略 | 存在输入、查询、展示或输出数据时包含 |
| 3.x.4 业务规则与状态变化 | 可省略 | 存在局部规则或状态变化时包含 |
| 3.x.5 交互流程 | 必需 | 每个功能点必须有 |
| 3.x.6 异常处理 | 可省略 | 存在异常、失败或边界场景时包含 |
| 3.x.7 外部依赖 | 可省略 | 存在接口或跨模块依赖时包含 |

**编写示例：** 时间筛选需写可选范围、默认值、匹配逻辑和无结果处理；不写筛选组件位置、宽高、颜色、圆角或阴影。
