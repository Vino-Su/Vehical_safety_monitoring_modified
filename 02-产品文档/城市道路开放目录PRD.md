## 1 背景

1. 现状问题：襄阳市智能网联开放道路资源分散、管理缺乏标准化，全市符合测试条件的城市道路缺乏统一台账，道路开放范围、开放时段与管控要求无法作为测试示范业务的合规依据被系统引用。
2. 建设目标：建立全市开放测试城市道路的统一资源目录，以道路为维度覆盖"建档 → 状态管控"的管理闭环，确保道路数据的完整性、一致性和可追溯性；通过差异化准入配置实现道路资源按自动驾驶等级、应用场景、业务类型的精细化分配。
3. 模块定位：城市道路开放目录是开放道路资源管理模块的基础分组。道路目录数据是地图可视化、区域统计查询、开放道路评估管理的数据基础，也是测试示范监管模块准入申请中选择道路路段的唯一合规来源。
4. 本文档与《开放道路管理模块PRD.md》的关系：本文档是该模块 PRD 中 F01、F02 两个功能点的分组级 PRD，业务规则与术语沿用模块 PRD；两个功能点的需求变更需同步维护两份文档。

## 3 产品定义与说明

### 3.1 产品定义

城市道路开放目录服务于政府监管部门与第三方服务机构，解决开放道路资源"无统一台账、管控无依据"的问题。主要使用路径：

1. 管理人员通过「道路信息建档」完成道路基础信息、空间属性、交通运行、基础设施、开放管控五类信息的录入与维护，形成全市统一道路台账。
2. 管理人员通过「道路资源动态管控」执行道路开放状态变更（暂停/关闭/恢复）、维护差异化准入配置、查看道路关联的在途申请流程与历史变更记录。
3. 产业运营主体在准入申请中选择道路时，只能选择目录内开放状态且准入范围匹配的道路（详见 4.5 联动规则）。

### 3.2 与现有系统的关系

| 关联系统/模块            | 获取或回传内容                                  | 使用场景                        | 本期关系 |
| ------------------ | ---------------------------------------- | --------------------------- | ---- |
| 测试示范监管 - 准入申请      | 获取：与道路关联的准入申请流程数据；回传：暂停/关闭道路时向监管模块发送任务终止指令 | 关联申请流程查看、状态变更联动             | 双向联动 |
| 测试示范监管 - 准入审批      | 审批通过的路段信息与道路数据关联                          | 关联申请流程的有效性判定                | 数据引用 |
| 开放道路资源管理 - 开放道路评估管理 | 道路建档/编辑保存、暂停恢复开放时触发单条道路自动评估               | 道路信息变更后的评估联动                | 上游触发 |
| 开放道路资源管理 - 地图可视化/区域统计 | 道路基础数据、开放状态数据                             | 地图渲染与区域统计的数据源               | 下游消费 |

### 3.3 产品边界

- 本期覆盖：城市道路开放目录分组下的道路信息建档（F01）、道路资源动态管控（F02）两个功能，以及配套的导入导出、状态流转、准入配置、变更记录规则。
- 本期不覆盖：地图可视化展示、区域统计查询、评估结果管理、评估指标配置、评估日志管理（见《开放道路管理模块PRD.md》对应章节）；道路信息编辑与准入配置的审批流程（见待确认问题 Q5）。

## 4 流程、规则与状态

### 4.1 道路开放状态流转

| 当前状态 | 触发操作 | 前置条件            | 目标状态 | 系统处理                                                      |
| ----- | ----- | --------------- | ---- | --------------------------------------------------------- |
| 开放    | 暂停    | 变更原因必填（≤200 字符） | 暂停   | 更新状态；写入变更记录；若存在进行中关联申请流程，弹窗警告并需二次确认，确认后向测试示范监管模块发送任务终止指令 |
| 开放    | 关闭    | 同上              | 关闭   | 同上                                                        |
| 暂停    | 恢复    | 变更原因必填（≤200 字符） | 开放   | 更新状态；写入变更记录；触发该道路单条自动评估                                  |
| 暂停    | 关闭    | 变更原因必填（≤200 字符） | 关闭   | 同"开放-关闭"行的系统处理                                             |
| 关闭    | 恢复    | 变更原因必填（≤200 字符） | 开放   | 更新状态；写入变更记录；触发该道路单条自动评估                                  |

- 状态变更一律通过 6.2.2 状态变更弹窗执行，不提供列表行内直接变更。
- 每次状态变更必须记录操作人、操作时间与变更原因。

### 4.2 编号生成规则

道路编号全局唯一，规则：前缀 `RD` + 年月 `YYYYMM` + 3 位数字序号（从 001 开始，每月重置）。示例：`RD202604001`。编号由系统自动生成，新建后不可修改。

### 4.3 唯一性规则

1. 道路编号全局唯一（系统生成保证）。
2. 同一道路下，差异化准入配置的"自动驾驶等级 + 适用应用场景 + 适用业务类型"组合不可重复。

### 4.4 删除规则

1. 删除方式为逻辑删除（标记删除状态），不物理删除数据，保留追溯能力。
2. 删除前系统校验该道路是否存在进行中的关联申请流程：存在则阻断删除并提示"该道路存在正在进行的关联申请流程，无法删除"；不存在方可执行。
3. 删除成功后记录删除操作日志（操作人、操作时间、操作内容），列表刷新。

### 4.5 数据联动规则

| 触发事件             | 联动行为                                                        |
| ---------------- | ----------------------------------------------------------- |
| 道路建档/编辑保存成功      | 触发该道路单条自动评估（开放道路评估管理）；字段变更写入变更记录（6.2.5）                     |
| 道路状态变更为暂停/关闭     | 向测试示范监管模块发送关联任务终止指令；该道路在准入申请的道路选择列表中自动过滤                     |
| 道路状态由暂停恢复为开放     | 触发该道路单条自动评估                                                 |
| 差异化准入配置保存成功      | 新准入范围即时生效，作为准入申请提交时道路与场景匹配校验的依据（见 6.2.4）                    |
| 道路基础数据/开放状态变化    | 同步供地图可视化、区域统计查询、车辆运行路段引用使用                                   |

**适用应用场景口径**：道路建档与差异化准入配置中的"适用应用场景"是准入申请道路选择和提交校验的唯一场景范围来源；道路可同时支持多个场景，申请侧每次选择一个应用场景。

### 4.6 表单校验规则

| 校验类型       | 校验条件                    | 失败处理                    | 是否阻断 |
| ---------- | ----------------------- | ----------------------- | ---- |
| 必填项        | 必填字段为空                  | 提示"请填写{字段名}"，弹窗不关闭      | 是    |
| 路段长度       | ≤ 0 或非数字                | 提示"路段长度必须为正数"           | 是    |
| 车道数        | ≤ 0 或非整数                | 提示"车道数必须为正整数"           | 是    |
| 开放时段       | 结束时间 ≤ 开始时间             | 提示"结束时间必须晚于开始时间"        | 是    |
| 道路名称长度     | 超过 50 字符                | 提示"道路名称不得超过 50 个字符"     | 是    |
| 文本域长度      | 管控要求说明/通行管控要求/变更原因超过 200 字符 | 提示"内容不得超过 200 个字符"      | 是    |
| 边缘计算节点数量   | "是否部署边缘计算节点"为"是"时为空或非正整数 | 字段下方红色错误提示              | 是    |
| 准入配置必选项    | 适用应用场景或适用业务类型为空         | 提示"适用应用场景和适用业务类型至少各选择一项" | 是    |
| 数字字段       | 照明等级、信号灯数量、RSU 配置数量、感知设备数量须为非负整数；最大坡度须为 0~100 | 字段下方红色错误提示       | 是    |

### 4.7 字段联动规则

| 触发字段           | 触发条件      | 联动行为                                     |
| -------------- | --------- | ---------------------------------------- |
| 是否部署边缘计算节点（建档表单） | 选择"是"     | 显示"边缘计算节点数量"字段且必填（正整数）                   |
| 是否部署边缘计算节点（建档表单） | 选择"否"     | 隐藏"边缘计算节点数量"字段并清空其值                      |
| 开放状态（建档表单）     | 选择"关闭"    | 开放时段开始/结束时间置灰不可填、不必填                     |
| 开放状态（建档表单）     | 选择"开放/暂停" | 开放时段开始/结束时间恢复可填且必填                       |

## 6 功能需求

### 6.1 F01 道路信息建档

#### 6.1.1 道路列表

1. 功能入口：开放道路资源管理 → 城市道路开放目录 → 道路信息建档。默认加载当前用户数据权限范围内的全部道路，按更新时间倒序排列，分页默认每页 10 条（可选 10/20/50/100）。
2. 筛选条件：道路名称（模糊搜索）、所属区域（下拉单选，关联襄阳市行政区划字典，默认全部）、道路等级（下拉单选：主干道、次干道、支路、快速路、园区道路，默认全部）、开放状态（下拉单选：开放、暂停、关闭，默认全部）、适用应用场景（下拉多选：无人物流、无人环卫、无人公交、无人出行，默认全部）。点击"查询"按当前条件刷新列表；点击"重置"清空全部条件恢复默认并刷新。
3. 列表字段：

| 序号 | 字段名        | 字段标识                | 说明                              |
| -- | ---------- | ------------------- | ------------------------------- |
| 1  | 复选框        | —                   | 用于导出选择；表头全选仅选中当前页，不支持跨页         |
| 2  | 道路编号       | road_code           | 系统自动生成，规则见 4.2                  |
| 3  | 道路名称       | road_name           | —                               |
| 4  | 所属区域       | district            | —                               |
| 5  | 道路等级       | road_level          | —                               |
| 6  | 车道数        | lane_count          | 单向车道数                           |
| 7  | 开放状态       | open_status         | 标签展示：开放/暂停/关闭                   |
| 8  | 开放时段       | open_hours          | 格式 HH:mm-HH:mm；关闭状态显示 "-"       |
| 9  | 适用应用场景     | application_scenes  | 多值以 "/" 分隔                      |
| 10 | 适用业务类型     | business_types      | 多值以 "/" 分隔                      |
| 11 | 更新时间       | update_time         | 格式 YYYY-MM-DD HH:mm             |
| 12 | 操作         | —                   | 查看、编辑、删除                        |

4. 操作列规则：查看对全部可访问角色显示；编辑、删除仅对政府监管部门、第三方服务机构显示。
5. 无符合条件的数据时列表展示空状态，不保留上一次查询结果。

#### 6.1.2 新建 / 编辑道路

1. 新建与编辑共用同一表单弹窗。新建时道路编号自动生成并置灰不可修改，开放时段默认 08:00-20:00；编辑时表单预填当前数据，道路编号置灰不可修改。

| 道路名称     | 文本输入   | 是    | —         | 最长 50 字符，如"长虹北路"                |
| 所属行政区域   | 下拉单选   | 是    | 襄阳市行政区划字典 | 不可为空                            |
| 道路等级     | 下拉单选   | 是    | —         | 枚举值：主干道、次干道、支路、快速路、园区道路         |
