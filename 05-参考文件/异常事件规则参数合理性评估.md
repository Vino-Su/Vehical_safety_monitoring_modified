# 异常事件规则参数合理性评估

| 项目 | 内容 |
| --- | --- |
| 评估对象 | 异常事件规则配置模块 |
| 评估日期 | 2026-09-30 |
| 评估依据 | 《异常状态事件 PRD》F15-3、现有异常事件规则配置页面、车辆异常事件体系、异常状态事件页面 |
| 评估目标 | 判断各规则参数是否有明确监管价值、数据来源和工程落地条件，控制一期建设投入 |

## 一、评估结论

异常事件规则配置一期建议采用“系统预置触发条件 + 少量阈值可调 + 企业/车辆/有效区域适用范围 + 必要时段配置”的模式。多条件组合应由系统模板固定，支持明确的“且/或”逻辑，不提供自由表达式编辑。

一期优先落地车速超限、数据中断、电子围栏越界、临牌有效期、测试时段和安全员状态等已有稳定数据来源的规则。碰撞模型、设备级故障、排班和多来源时段等参数，需在接口、数据质量和业务口径验收后再开放。

## 二、逐规则参数合理性

结论含义如下：

- **保留**：有明确业务价值，数据来源已有或容易形成，适合作为一期配置项。
- **条件保留**：有业务价值，但需要数据质量、外部模块或权限条件，建议限制为平台管理员或后续版本开放。
- **系统固定**：规则需要该逻辑，但不适合让业务人员自由调整，应由系统模板、外部业务数据或后台参数确定。
- **暂不建设**：当前投入高、收益低、定义不清或容易造成漏报误报，一期不提供配置。

| 规则子类型 | 当前或候选参数 | 评估结论 | 工程实施与投入产出判断 | 一期建议 |
| --- | --- | --- | --- | --- |
| 车速剧烈突变 | 速度变化阈值、统计窗口、减速度阈值、持续/重复次数 | 基本合理，需收敛 | 速度时序数据可直接计算；同时开放多个相近参数会增加调参成本和重复触发 | 保留速度变化阈值、统计窗口；减速度和连续次数先使用系统默认值 |
| 加速度剧烈突变 | 纵向加速度阈值、横向加速度阈值、持续时间 | 条件保留 | 规则与现有事件口径一致，但不同车企的单位、采样频率和噪声可能不同 | 接口和数据质量验收后开放；默认值由平台维护 |
| 超时停靠 | 普通道路阈值、园区/低速道路阈值、重点位置阈值、位移阈值、静止车速阈值 | 部分过度设计 | 分场景阈值依赖道路分类、重点位置标签和定位质量；多套时长的维护成本较高 | 保留静止车速、位移和一个停靠时长；重点位置阈值作为后续扩展 |
| 车速超限 | 速度容差、速度容差百分比、持续时间、限速来源 | 容差设置需收敛 | 道路和围栏限速已有来源；同时配置绝对值和百分比会产生冲突 | 限速来源系统自动取有效且更严格值；只保留一种容差模式和持续时间 |
| 倒车预警 | 持续时间、适用车辆类型、作业区豁免 | 部分过度设计 | 倒挡、车速和驾驶模式已有实时数据；车辆类型属于适用范围，作业区豁免属于另一类策略 | 保留持续时间；车辆类型移到适用范围；不建设作业区豁免 |
| 碰撞预警 | 模型置信度阈值、严重程度映射方案 | 条件保留 | 置信度取决于模型校准和版本；严重程度映射属于模型或事件分类结果，不宜由规则管理员修改 | 置信度仅对平台管理员开放或系统固定；严重程度映射系统固定 |
| 数据中断 | 普通车辆离线阈值、低速无人车离线阈值、连续丢包次数 | 前两项条件合理，丢包次数过度 | 离线时长基于心跳数据，容易解释；丢包次数依赖统一报文序号和采样协议，且与离线时长重复 | 保留离线时长；只有在上报频率已标准化时才按车辆类型设置不同阈值；连续丢包次数系统固定 |
| 传感器故障 | 故障持续时长、连续异常采样次数、关键设备范围 | 部分过度设计 | 故障码和持续时间有价值；设备范围自由勾选依赖跨车型设备字典，错误配置会漏报 | 保留故障持续时长；采样次数和设备范围由系统默认或车型配置确定 |
| 终端异常“其他” | 异常码持续时长、连续上报次数 | 过度设计 | “其他”没有统一异常语义，无法证明一套通用阈值适合所有故障码 | 一期只保留启停、适用范围和时段；先完善故障码分类 |
| 临牌过期上路 | 宽限时间、适用临牌状态 | 宽限时间不合理 | 该规则是合规判定，应以临牌登记有效期为准；可配置宽限会削弱监管边界 | 取消宽限时间和状态选择，直接读取临牌有效期和车辆运行状态 |
| 允许通行区域越界 | 越界缓冲距离、持续时间、连续采样次数 | 部分合理 | 缓冲距离和短暂持续时间可抑制 GPS 漂移；连续采样次数与持续时间作用重复 | 保留缓冲距离和持续时间；连续采样次数系统固定 |
| 禁行区域闯入 | 闯入缓冲距离、持续时间、连续采样次数 | 高风险规则，需严格收敛 | 容错过大或持续过长会延迟合规告警；采样次数也会增加延迟 | 保留小范围缓冲和短暂持续时间；采样次数系统固定，参数范围由平台管理员控制 |
| 区域外激活自动驾驶 | 授权区域来源、缓冲距离、持续时间、连续采样次数 | 区域来源不应自由配置 | 授权道路、允许围栏和转场路段应由已批准申请统一确定；任意勾选来源可能绕过授权关系 | 区域来源系统按授权数据确定；保留缓冲距离和持续时间；采样次数固定 |
| 非规定时段测试 | 允许时段来源、宽限时间 | 过度设计风险较高 | 允许时段来自准入申请、道路和区域配置；自由选择来源或设置宽限会改变许可边界 | 来源只读并按既定优先级合并；取消可配置宽限时间 |
| 高峰时段运行 | 早晚高峰时间段、适用车辆类型、宽限时间 | 时间段合理，宽限时间过度 | 高峰时段和车辆类型直接决定是否监管；宽限时间会造成合规口径不一致 | 保留一个或多个高峰时间段、车辆类型和管控区域；取消宽限时间 |
| 安全员未到岗 | 排班来源、心跳超时时长、适用安全员类型 | 与当前需求存在冲突 | 最新需求倾向实时检测安全员在岗信号；多个排班来源会引入同步、优先级和冲突处理成本 | 以实时在岗/心跳数据为主，保留短暂判定时长；排班来源暂不开放 |
| 安全员异常离岗 | 排班来源、离岗持续时间、恢复判定时长、适用安全员类型 | 部分过度设计 | 离岗持续时间有价值；恢复判定属于事件闭环，不属于当前规则配置范围；排班来源依赖外部同步 | 保留离岗持续时间；移除恢复判定时长和多来源排班配置 |

## 三、跨规则配置维度

| 配置维度 | 合理范围 | 过度设计或风险 | 建议 |
| --- | --- | --- | --- |
| 多条件组合 | 使用系统预置的且/或关系，例如驾驶模式、定位、档位、车速同时满足 | 通用表达式、任意嵌套逻辑、修改核心字段 | 允许调整阈值，不允许修改驾驶模式、档位、定位等核心触发字段；每条规则固定条件数量和逻辑 |
| 适用企业 | 企业多选 | 企业与车辆规则冲突时无优先级 | 明确企业、车辆类型、指定车辆的交集关系；指定车辆应继承所属企业校验 |
| 适用车辆类型 | 乘用车、商用车、专用作业车、功能型低速无人车等枚举 | 在每条规则中重复配置车辆类型和专用参数 | 车辆类型用于适用范围；与规则阈值分离，避免把范围字段当成参数字段 |
| 指定车辆 | 少量例外车辆选择 | 大批量逐车维护、车辆变更后规则失效 | 作为例外能力后置；默认按企业和车辆类型生效 |
| 特定区域 | 已有道路、电子围栏、重点位置 | 自由绘制区域或在规则页重复维护地理数据 | 只引用道路资源和电子围栏管理中的有效对象 |
| 业务类型 | 道路测试、示范应用、商业化试点 | 与准入申请业务类型不一致时产生重复维护 | 可作为条件保留项；优先从准入申请自动带出，不允许手工录入 |
| 预警时段 | 全天、规则专用时间段 | 工作日/节假日/自定义日期范围全部开放，且与授权时段重复配置 | 一期默认全天；仅高峰时段等确有政策要求的规则开放时间段，法定或授权时段从业务数据读取 |
| 启停状态 | 单条启用/停用 | 批量停用关键合规规则 | 保留单条操作和权限控制；关键规则停用需记录原因并二次确认 |
| 版本记录 | 保存规则编号、版本、操作人、时间和变更前后值 | 把每个运行事件都复制为规则版本 | 保留配置版本，用于事件追溯；运行事件只记录命中的规则编号和版本 |
| 豁免、去重恢复、通知 | 属于事件生成和事件闭环能力 | 放在规则页会扩大范围并与异常事件处置重复 | 不纳入本模块，按事件引擎、消息中心和处置流程分别建设 |

## 四、一期实施优先级

| 优先级 | 建设内容 | 原因 |
| --- | --- | --- |
| P0 | 规则启停、核心条件只读、车速超限、数据中断、临牌有效期、电子围栏越界、非规定时段测试、企业/车辆/有效道路和围栏范围、必要时间段 | 数据来源明确，监管价值高，能够直接支撑现有异常事件页面 |
| P1 | 车速剧烈突变、加速度剧烈突变、超时停靠、高峰时段运行、安全员未到岗/异常离岗 | 有业务价值，但依赖采样质量、车辆状态或外部排班/状态接口 |
| P2 | 碰撞模型置信度、传感器设备范围、指定车辆例外、多来源时段合并 | 需要模型校准、设备字典、数据同步和冲突处理，适合后续精细化运营 |
| 暂不建设 | 终端异常“其他”的通用阈值、临牌宽限时间、合规规则宽限时间、自由表达式、豁免/去重恢复/通知策略 | 定义不稳定或会削弱合规口径，投入产出比低 |

## 五、现有页面的工程实现风险

1. 现有页面的参数模板仍包含部分待收敛字段，例如车速超限同时展示绝对容差和百分比容差、数据中断展示连续丢包次数、传感器故障展示设备范围。
2. 现有页面的“保存配置”目前主要更新启停状态、版本号和更新时间，尚未完整提交阈值、适用范围和生效时段字段；正式开发时需要补充表单取值、后端校验、保存失败保留输入和版本快照。
3. 异常事件页面包含“偏离路线”等运行异常子类型，规则配置页面的预置规则清单需要与事件页面统一，否则会出现事件可展示但没有对应规则配置的情况。
4. 规则配置页面中的“预警时段”必须与异常事件中的法定或授权时段判定分开，不能通过关闭规则或配置宽限时间绕过准入约束。

## 六、评审结论

建议确认一期范围为：系统固定核心触发条件，开放少量经验证的阈值，支持企业、车辆类型、指定车辆和有效道路/围栏的适用范围，按规则需要配置时段；取消或后置豁免、去重恢复、通知策略、自由表达式、合规宽限和未定义“其他”异常码阈值。

## 七、车速剧烈突变参数方案

### 7.1 规则定义

车速剧烈突变属于车辆运行异常预警，建议将核心判定固定为：

```text
驾驶模式 = 自动驾驶
且实时车速数据有效
且（abs(v(t) - v(t-W)) >= ΔV 或纵向减速度 <= A）
且连续满足确认条件
```

其中，`ΔV` 为速度变化阈值，`W` 为统计窗口，`A` 为减速度阈值。速度变化和减速度之间使用“或”关系，任一指标达到风险阈值即可触发同一条预警，不生成两条重复事件。

### 7.2 参数建议

| 参数             | 是否开放配置           | 建议范围/默认值              | 参数作用                  | 实施要求                                          |
| -------------- | ---------------- | --------------------- | --------------------- | --------------------------------------------- |
| 速度变化阈值 ΔV      | 保留，限平台管理员或规则授权人员 | 10~30 km/h，默认 15 km/h | 识别统计窗口内的速度突增或突降       | 统一使用车辆实时速度，单位统一为 km/h；不建议继续使用 1~80 km/h 的过宽范围 |
| 统计窗口 W         | 保留，和 ΔV 联动校验     | 2~5 s，默认 3 s          | 规定比较当前速度与历史速度的时间跨度    | 窗口内至少应有 3 个有效采样点；采样不足时不判定                     |
| 纵向减速度阈值 A      | 条件保留，默认系统值       | -2~-5 m/s²，默认 -3 m/s² | 捕捉强制动但速度差尚未达到 ΔV 的情况  | 优先使用车端纵向加速度；不同车辆单位、方向定义不一致时由系统适配，不交给业务人员修正    |
| 连续满足次数         | 系统固定，不建议页面开放     | 默认连续 2 次              | 过滤单个异常包或瞬时抖动          | 当前数据刷新要求不低于 1Hz；确认次数会增加约 1 个采样周期的告警延迟，应记录实际延迟 |
| 触发逻辑           | 系统固定             | ΔV 或 A                | 保持与车辆异常事件体系一致         | 不提供 AND/OR 自由切换，否则会改变既定监管口径                   |
| 数据有效性校验        | 系统固定             | 时间戳递增、采样间隔有效、速度非空     | 防止报文乱序、重复包、长时间缺包造成假突变 | 发现时间戳跳变、采样间隔超限或数据缺失时跳过本次计算，并记录数据质量原因          |
| 驾驶模式条件         | 系统固定             | 自动驾驶                  | 排除人工驾驶下的正常驾驶操作        | 不作为普通参数输入，直接引用车辆实时驾驶模式                        |
| 人工接管、紧急制动测试等场景 | 暂不在本模块配置         | 按业务数据或任务状态识别          | 避免已知测试动作产生无效预警        | 现阶段由事件引擎引用任务状态；不在规则页新增豁免条件                    |

### 7.3 推荐的初始配置

| 配置项    | 推荐值                 | 说明                        |
| ------ | ------------------- | ------------------------- |
| 速度变化阈值 | 15 km/h             | 延续现有车辆异常事件体系的建议值          |
| 统计窗口   | 3 s                 | 与现有 `v(t)-v(t-3s)` 判定口径一致 |
| 减速度阈值  | -3 m/s²             | 识别明显急减速，避免把普通制动当作异常       |
| 连续满足次数 | 2 次                 | 过滤单点噪声；作为系统默认，不对普通监管人员开放  |
| 触发组合   | 速度变化达到阈值或减速度达到阈值    | 保证急减速和明显速度跳变都能被识别         |
| 生效范围   | 默认按车辆类型、企业和有效业务范围继承 | 范围配置与阈值配置分离，避免为每辆车复制一套参数  |
| 生效时段   | 全天                  | 除非监管政策明确要求特定时段，否则不增加时段限制  |

### 7.4 数值联动和边界校验

1. `W` 越大，允许的速度变化阈值应同步评估；禁止出现窗口为 5 秒但仍沿用仅适合 1 秒窗口的阈值。
2. `ΔV` 不得低于 10 km/h；低于该值时，普通速度波动和定位或报文抖动可能被误判为异常。
3. `A` 不得接近 0；例如设置为 `-0.5 m/s²` 会把正常减速大量识别为异常。
4. 当速度变化和减速度同时命中时，只生成一条事件，并在事件详情中记录命中指标、实际值、阈值、统计窗口和规则版本。
5. 当连续确认未完成但车辆已恢复正常，不生成事件；这属于触发确认逻辑，不等同于事件去重或恢复配置。
6. 速度、加速度单位和正负方向必须在接入层统一。接入层未完成标准化前，不应开放企业级参数调整。

### 7.5 典型场景

| 场景 | 数据示例 | 是否触发 | 说明 |
| --- | --- | --- | --- |
| 明显加速 | 3 秒前 20 km/h，当前 36 km/h | 触发 | 速度变化 16 km/h，超过 15 km/h |
| 明显减速 | 3 秒前 50 km/h，当前 34 km/h | 触发 | 速度变化绝对值 16 km/h，超过 15 km/h |
| 强制动但速度差较小 | 速度变化 8 km/h，纵向减速度 -3.2 m/s² | 触发 | 命中减速度分支 |
| 单点异常包 | 50 → 8 → 50 km/h，仅 1 个异常采样点 | 不触发 | 未满足连续确认，且应进入数据质量记录 |
| 人工驾驶急刹 | 车辆处于人工驾驶，纵向减速度 -4 m/s² | 不触发 | 驾驶模式条件不满足 |

### 7.6 最终建议

一期页面建议只展示“速度变化阈值”和“统计窗口”两个可编辑参数；“减速度阈值”可在平台管理员模式下开放，或先使用系统默认值；“连续满足次数、触发逻辑、数据质量校验、驾驶模式条件”全部由系统固定。这样既保留了规则对不同车辆和企业的适配能力，也避免把采样噪声、算法口径和事件闭环配置转嫁给业务人员。
