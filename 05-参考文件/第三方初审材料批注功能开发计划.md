## 一、目标与范围

### 1.1 开发目标

在第三方初审环节，允许审批人针对具体申请材料填写文本批注。退回时，系统根据已保存批注自动生成问题清单并随整体审批结论提供给申请主体，减少“材料不完整”等无法定位问题的退回意见。

### 1.2 本次范围

| 范围 | 规则 |
|---|---|
| 可操作节点 | 仅第三方初审 |
| 批注内容 | 单个材料对应一段文本说明 |
| 批注字段 | 材料编号、材料名称、问题说明；材料编号和名称从申请材料目录自动带出 |
| 批注操作 | 新增、修改、删除、保存草稿 |
| 退回结果 | 生成问题清单，包含材料和问题说明 |
| 重新提交 | 第三方初审复核时显示对应材料的历史批注，只读 |
| 后续节点 | 专班审核、专家评审、专题会审议不显示批注和历史批注入口；需要追溯时查看流程日志 |
| 未批注材料 | 默认无问题，不新增材料核验状态 |

### 1.3 明确不做

- 不提供材料级“通过/退回”审批。
- 不增加“待核验、已核验、需补正”等材料状态。
- 不增加问题类型、页码/位置、批注人、批注时间等申请人可见字段。
- 不在专家评审、专班审批等后续节点显示材料批注入口。
- 不建设 PDF 在线高亮、画笔批注或复杂版本比对。

## 二、业务流程

### 2.1 第三方初审流程

1. 审批人进入第三方初审审批详情，查看申请信息和材料目录。
2. 需要指出问题时，点击材料行的“批注”，填写问题说明并保存。
3. 已保存批注的材料显示轻量提示和“查看/编辑批注”入口；没有批注的材料保持现有展示。
4. 审批人点击“通过”时，沿用现有备注必填校验；批注可有可无。
5. 审批人点击“退回”时，沿用现有备注必填校验，并校验至少存在一条材料批注。
6. 校验成功后，系统将材料批注汇总为问题清单，写入本次审批记录和流程日志，并通知申请主体。

### 2.2 退回后重新提交

1. 申请主体根据问题清单修改对应材料并重新提交。
2. 申请重新进入第三方初审时，材料行提供“历史批注”入口。
3. 历史批注只读展示上一次退回时的材料名称和问题说明，不与当前批注混合。
4. 第三方初审人员可在同一材料下新增本轮批注；本轮批注保存后成为当前审批记录。
5. 通过复核后，历史批注仍保存在流程日志中，但不再在后续节点材料列表中展示。

### 2.3 其他审批节点

- 专班审核、专家评审、专题会审议沿用现有整体审批、审批意见/备注和审批附件功能。
- 这些节点的材料行不渲染“批注”和“历史批注”操作。
- 如需了解初审问题，通过流程日志查看第三方初审记录及问题清单。

## 三、数据与接口设计

### 3.1 批注数据对象

建议以“申请 + 审批节点 + 材料编号 + 审批轮次”为关联维度保存，不修改申请材料原始目录。

| 字段                  |  必填 | 说明                       |
| ------------------- | --: | ------------------------ |
| applicationId       |   是 | 申请编号                     |
| approvalNode        |   是 | 固定为 `third_party_review` |
| round               |   是 | 第三方初审轮次；首次为 1，退回重提后递增    |
| materialId          |   是 | 申请材料编号                   |
| materialName        |   是 | 提交时固化的材料名称               |
| content             |   是 | 批注文本，建议限制 2000 字以内       |
| deleted             |   是 | 软删除标记，保证流程日志可追溯          |
| createdAt/updatedAt |   是 | 系统记录，用于审计，不作为申请人页面展示字段   |

### 3.2 问题清单快照

退回提交时生成不可变的问题清单快照，避免申请材料目录后续变化导致历史退回内容失真。

```json
{
  "applicationId": "RT202604001",
  "approvalNode": "third_party_review",
  "round": 1,
  "items": [
    {
      "materialId": 4,
      "materialName": "机动车整车出厂合格证",
      "content": "证书中的车辆型号与申请信息不一致"
    }
  ]
}
```

### 3.3 建议接口

接口名称按现有后端命名规范落地，以下为业务能力要求：

| 能力 | 触发节点 | 要求 |
|---|---|---|
| 查询当前轮次批注 | 第三方初审 | 返回当前申请、当前轮次下未删除批注 |
| 保存批注 | 第三方初审 | 校验材料属于当前申请，批注内容非空 |
| 修改/删除批注 | 第三方初审 | 仅允许当前审批人或具备该节点权限的人员操作 |
| 查询历史批注 | 第三方初审复核 | 返回最近一次退回的问题清单或按轮次查询 |
| 提交审批 | 第三方初审 | 退回时校验批注数量并生成问题清单快照 |
| 查询流程日志 | 所有节点 | 展示第三方初审的整体备注和问题清单 |

### 3.4 权限与并发

- 只有拥有第三方初审处理权限的角色可以新增、修改、删除当前轮次批注。
- 无第三方初审权限的用户只能按既有权限查看流程日志。
- 提交审批时以后端再次校验节点、申请状态和批注数据，避免仅依赖前端校验。
- 同一申请被其他人处理后，当前页面提交应提示数据已更新并阻止覆盖。

## 四、前端开发任务

| 编号 | 任务 | 交付结果 |
|---|---|---|
| FE-01 | 判断当前审批节点 | 仅 `pending_review` 渲染批注入口；其他节点不渲染 |
| FE-02 | 材料行增加批注入口 | 保留现有预览、下载和关联档案操作，新增批注入口 |
| FE-03 | 批注编辑弹窗 | 展示材料编号、材料名称、单个文本框、取消、保存；支持编辑已有批注 |
| FE-04 | 批注删除 | 删除前二次确认；删除后刷新当前轮次批注展示 |
| FE-05 | 当前批注提示 | 已批注材料显示轻量提示和查看/编辑入口，不展示材料状态 |
| FE-06 | 历史批注展示 | 仅第三方初审复核显示，历史内容只读；后续节点隐藏入口 |
| FE-07 | 审批底部汇总 | 展示“已标注问题：N项”；退回时提示将生成问题清单 |
| FE-08 | 提交校验 | 退回无批注时阻止提交；通过不要求批注；备注规则保持不变 |
| FE-09 | 流程日志展示 | 第三方初审日志增加问题清单折叠区；其他节点仅按现有日志查看 |
| FE-10 | 申请主体结果展示 | 在申请主体可见的退回结果/详情中展示材料和问题说明，不展示内部审计字段 |

## 六、测试计划

### 6.1 功能测试

- 第三方初审可以对任意材料新增批注。
- 批注为空时不能保存；保存后可查看、修改和删除。
- 通过时无批注也可提交，但备注仍必填。
- 退回无批注时不能提交，并给出明确提示。
- 退回后问题清单只包含本轮实际批注材料。
- 重新提交后第三方初审可查看历史批注，历史内容不可编辑或删除。
- 专班、专家、会议节点不显示批注和历史批注入口。
- 流程日志可查看历次第三方初审的问题清单。

### 6.2 边界与异常测试

- 材料名称变更、材料被替换、派生申请和原申请关联材料不误关联。
- 连续新增多条材料批注，问题清单顺序与材料目录一致。
- 删除批注后退回校验不计入问题数量。
- 重复点击保存、通过、退回不会生成重复记录。
- 网络失败时保留已填写文本并提示未保存，不产生半条问题清单。
- 无权限用户无法调用批注写接口。
- 退回提交过程中申请已被其他人处理时，阻止覆盖并提示刷新。

### 6.3 页面自测

使用现有页面自测方式验证至少以下场景：

- `approve.html#approve-demo`：第三方初审材料批注、退回问题清单。
- 第三方初审复核：历史批注展示及只读约束。
- 专班/专家审批详情：材料行不出现批注入口。
- 1366×768 和小屏宽度下，批注弹窗、材料长名称和底部审批区不溢出。

## 七、验收标准

1. 只有第三方初审节点可以操作单个材料批注。
2. 批注只有文本说明，不新增问题类型、核验状态和复杂定位字段。
3. 未批注材料默认无问题，页面不显示额外核验状态。
4. 退回必须至少有一条材料批注，系统自动生成问题清单。
5. 问题清单仅向申请主体展示材料和问题说明；批注人、批注时间等字段不对外展示。
6. 退回重提后，第三方初审可以查看最近一次历史批注；历史批注只读。
7. 专班审核、专家评审、专题会审议不展示批注或历史批注入口。
8. 流程日志可以追溯历次第三方初审的整体备注和问题清单。
9. 现有整体通过、整体退回、节点流转和审批附件功能不受影响。
10. 批注保存、审批提交、问题清单生成和通知具备服务端校验及审计记录。

## 九、发布与回滚

- 发布前备份涉及的高保真页面、产品文档和入口文件，遵循项目备份规则。
- 功能建议通过节点开关或权限配置控制，默认仅第三方初审角色开启。
- 回滚时关闭批注入口和写接口，不删除已经生成的问题清单及流程日志。
- 回滚后再次开启功能，历史批注仍按申请轮次读取，避免审批证据丢失。
